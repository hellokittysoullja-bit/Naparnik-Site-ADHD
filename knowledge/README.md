# База знаний «Напарника» — как ей пользоваться

Зачем: чтобы ни один приём, решение владельца или проверенный факт не терялся между сеансами и при сжатии контекста.
Всё здесь — в git, не в scratchpad (scratchpad стирается вместе с контейнером).

| Файл | Что внутри | Когда читать |
|---|---|---|
| `INDEX.md` | Одна страница: самое сильное, чек-лист ID по этапам, красные линии, опровергнутое | ВСЕГДА первым |
| `techniques.md` | Каталог всех приёмов: одна строка = один приём, сила доказательств, статус у нас, источник | Перед проектированием — разделы этапов, которые трогаешь |
| `decisions.md` | Решения и правила владельца с датами, факты о проде, уроки ошибок ИИ | Перед любым предложением владельцу |
| `../research/` | Полные отчёты (первоисточник для каждой строки каталога) | Когда нужна подробность или цитата |

## Протокол (обязателен для любого ИИ-сеанса)
1. **Начало задачи** про онбординг, воронку, тексты, кота, бота, пейвол, цены, рекламу → прочитать `INDEX.md` и `decisions.md`.
2. **Проектирование** → пройти чек-лист `INDEX.md` по КАЖДОМУ ID затронутых этапов. В ответе владельцу назвать, какие ID
   использованы и какие сознательно отброшены (и почему). Так приёмы не «забываются».
3. **Новое знание** (исследование, отчёт агента, видео, проверка) → полный отчёт в `research/NN-тема/`, приёмы — строками в
   `techniques.md` (следующий номер в конце своего раздела), при изменении «самого сильного» — обновить `INDEX.md`.
4. **Решение владельца** → строка в `decisions.md` с датой, дословно короткой цитатой.
5. **Ничего не удалять.** Устаревшее помечать: `~~строка~~ → см. ID` или статус «— решено не использовать (дата, почему)».
   ID не перенумеровывать никогда.
6. Цифры — только из источников. Поправки критика/проверок — писать исправленный вариант с пометой «(испр.)».
