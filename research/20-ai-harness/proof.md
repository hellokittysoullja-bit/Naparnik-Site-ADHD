# Обвязка «Напарника» против Hermes Agent и других: что доказано, а что нет

Версия 2 от 12.11.2026, после независимого аудита (ветка `claude/ai-harness`). Первая версия этого документа
утверждала «на уровне Hermes или лучше». Аудитор-архитектор сверил каждую строку с исходным кодом и это
утверждение в общем виде **не подтвердил**. Ниже — исправленная картина: что перенесено точно, что слабее
оригинала, где мы действительно сильнее и чего нет.

Чужой код — по коммитам: Hermes Agent `3bcd0712`, OpenAI Agents SDK JS `7589b9c`, Mastra `d546b6c5`, mem0
`f1791da`, Letta Code `ad308cd` (клоны разобраны в `hermes-code-analysis.md` и `harnesses-code-analysis.md`).
Наш код указан именами файлов и функций, а не номерами строк: номера съезжают при каждой правке.

## 0. Вердикт одной страницей

**Защитимая формулировка:** для одношагового компаньона приёмы Hermes, OpenAI Agents SDK и Mastra перенесены
выборочно и закреплены тестами. По задержке (страхующие запросы) и по незаметной смене модели до показа текста
обвязка сильнее разобранных. По памяти, наблюдаемости и оценочным прогонам — заметно слабее Hermes и Mastra.

Оценки аудитора на момент проверки (10 = Hermes и лучшие обвязки, с поправкой на задачу продукта) и что
изменилось после исправлений. Повторной независимой оценки после исправлений не было — правая колонка описывает
сделанное, а не новый балл.

## 2. Где мы сильнее — после проверки

| Утверждение | Вердикт аудита |
|---|---|
| Страхующие параллельные запросы с точкой фиксации | **Верно**: в Hermes, OpenAI, Mastra, mem0 и Letta параллельной гонки моделей нет. Сам приём известный (Dean и Barroso, 2013). Цена: при мгновенной страховке ход стоит двух запросов |
| Незаметная смена модели до показа текста | **Верно, это наше.** Сама проверка по предложениям есть у Mastra |
| Адаптивная страховка | Код верен, польза не доказана: состояние живёт в памяти экземпляра сервера, замера в продакшене нет |
| Кризисный ответ без модели | Верно, у Hermes протокола нет. Но словарь узкий (§4) |
| Нормализация Unicode с двойниками | Частично сильнее: Hermes делает NFKC и ловит невидимые символы, межалфавитных двойников не ловит |
| Сервер подставляет результат клиентского инструмента | Верно |
| Аргументы инструментов через проверку вывода | Добавлено после аудита |
| Чужая личность не показывается | Верно (правило по словам) |
| Запрет вызова модели в обход обвязки | Верно; после аудита закрывает любые `@ai-sdk/*` и весь репозиторий |
| ~~Устойчивая модель первой при подозрении на взлом~~ | **В продакшене не работает:** пометки `robust` нет ни у одной модели. Механизм и тест есть, пользы пока нет |
| ~~Ни одного непроверенного слова — у других такого нет~~ | **Неверно как «у других нет»:** у Mastra есть |

## 3. Чего нет

| Чего нет | Почему | Что нужно |
|---|---|---|
| Серверная память: хранение, поиск, правка, «забудь», свёртка | Базы нет; что хранить и что кот забывает — решения владельца | База и ответы на вопросы из `memory-personalization.md` |
| Память и персонализация вне чата | Голос сессии и дробление идут без памяти | Решение владельца: менять ли их ответы под человека |
| Хранилище истории для бота | `telegramTurn` получает историю от вызывающего | База |
| Многошаговый цикл агента | Инструменты исполняет устройство, ход одношаговый | Появится с серверными инструментами |
| Классификация ошибок провайдера с паузами | Сейчас следующая модель и код в журнале | Можно сделать без решений |
| Сменная абстракция проверок, модель-судья | Вшитые правила; судья — второй платный вызов | Интерфейс — без решений; судья — решение владельца |
| Спаны, экспорт трассировки, учёт стоимости | Одна строка журнала на ход | Можно сделать без решений |
| Лимиты расходов | Отложены владельцем; полуподключённый дневной лимит удалён, чтобы не вводить в заблуждение | Решение владельца |
| Свёртка разговора моделью | Детерминированная подрезка есть (`prompt/context-budget.ts`) | Второй платный вызов — решение владельца |
| Содержимое знаний | Каталог пуст намеренно | Список приёмов на утверждение |
| Транспорт бота | Ветка бота не влита | Разрешение владельца |

## 4. Аудит 12.11: что нашли и что сделано

Четыре независимых аудитора получили код без выводов автора.

**Корректность (9 дефектов, 7 воспроизведены запуском).** Исправлены все, кроме учёта чата в лимите токенов:
лимит удалён целиком до решения владельца.
- Негодный вызов инструмента уходил в браузер, тот сам слал историю заново — платная петля. Теперь негодный вызов
  не пересылается, а счётчик кругов видит и вызовы с ошибкой.
- Закрытая посреди ответа вкладка делала модель «медленной», и страховка запускала две модели на каждый ход.
- Второй текстовый блок терял конец первого; нумерованный список обходил правило двоеточия; запись в память
  терялась при отмене; ошибка 504 считалась таймаутом; исключение в разборе ответа съедало попытку.

**Безопасность.** Системная часть и журналы чистые, блок данных подделать не удалось, ReDoS нет.
- Аргументы инструментов шли мимо проверки вывода — закрыто.
- Кризис не ловил живые формулировки и разбивку знаками — добавлены однозначные фразы и новые прочтения.
  Двусмысленные («устал жить», «хочу исчезнуть», «мне очень плохо») ждут решения владельца.
- Проверка вывода блокировала 17 из 45 обычных реплик кота, 14 из них ложно — исправлено, таблица закреплена тестом
  (`ai-guards-audit.test.ts`).
- Ссылки (любая доменная зона, запись словами), номера (точки, тире, цифры других письменностей), скан записи
  в память, псевдоним Telegram без запасного ключа.

**Архитектура.** Вердикт и оценки — в §0, построчная сверка — в §1 и §2.

**Качество кода.** Из 28 нарочных поломок тесты ловили 19. На девять выживших (отмена, уже отменённый сигнал,
отмена после фиксации, исчерпание цепочки, потолок кругов, порог номера, дедупликация на устройстве) добавлены
тесты; девятая — дневной лимит — удалена вместе с кодом.

**Само-проверка 12.11 (после аудита, без агентов).** Чистая копия закоммиченного состояния собирается и
проходит все тесты; секретов и лишних файлов в истории нет. Утверждение «из 17 блокировок 14 были ложными»
подтверждено запуском (три оставшиеся — «постарайся», «надо было раньше», «должен был сдать» — блокируются
по замыслу). Нарочные поломки десяти механизмов: тесты поймали девять. Найдено и исправлено:
- разовые задачи (голос сессии, дробление) принимали ответ, оборванный по длине («…давай теперь»), — у чата
  такая защита была;
- проверка аргументов инструментов по правилам тона, лекарств и личности не была закреплена тестом (выживала
  поломка) — тесты добавлены.
Не исправлено, записано: память бота ключуется идентификатором из журнала, которого без `VISIT_SECRET` нет
(см. комментарий у `InProcessMemory`); боевой адаптер получит ключ от маршрута.

**Перед вливанием в main (12.11, после слияния с #93).** Проверка на соединённом коде: 269 модульных, 112
сквозных, сборка зелёная; предупреждений линтера 10 (как у main). Найдено и исправлено:
- без ключа AnyModel чат отвечал на Flash-Lite вместо Flash и не имел запасного пути через AI Gateway, как у
  main: маршруты без ключа теперь ведут себя как до обвязки (`models.ts`, `legacyChain`), тест есть;
- короткие домены без слэша («t.me», «x.com») проходили проверку ссылок (живая атака, модель написала шаг
  «Ввести три буквы t.me»): правило теперь ловит их, сокращения («т.е.», «U.S.A.», «p.s.») и имена файлов
  проходят.
Замер скорости чата, одна модель, 24 запроса на сторону: первое слово медиана 1,16 с (main) → 1,36 с, 90-й
процентиль 2,4 → 2,0 с, худший 6,6 → 4,0 с; весь ответ 1,36 → 1,37 с. Единственный минус — текст появляется
после первого проверенного предложения (+0,2 с к первому слову). Живые атаки: три прогона подряд 23 из 23.

**Найдено живым прогоном после аудита:** вступительная фраза модели попадала первым «шагом» дробления, третий шаг
терялся — исправлен разбор.

Не исправлено и перечислено в `lib/ai/README.md` («Чего обвязка не обещает»): лексическая природа правил, счётчик
кругов на доверии к клиенту, состояние в памяти процесса, неработающее звено `robust`.
