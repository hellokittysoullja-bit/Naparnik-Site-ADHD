# 20. Обвязка (harness) для ИИ-кота — структура и принципы (11.11.2026, на согласование владельцу)

Статус: **проект, не внедрён.** Внедрение — только после «да» владельца.

## 0. Что такое обвязка и зачем она нам

Модель только продолжает текст. Всё остальное делает обвязка: характер и правила кота, память о человеке, инструменты,
выбор модели и запасной, проверка ответа, лимиты и деньги, журнал, проверочный прогон перед выпуском.

Сейчас обвязки нет: три маршрута (`app/api/companion`, `app/api/breakdown`, `app/api/session-voice`) сами собирают промпт
и сами зовут модель; ветка `claude/telegram-bot` — ещё одна копия. Цель — **один «мозг кота» для всех каналов**
(сайт, Telegram, будущее приложение, внешний API).

## 1. На кого ориентируемся (открытый код, прочитан 11.11)

| Источник | Что у них | Что берём |
|---|---|---|
| **Hermes Agent** (Nous Research, github.com/NousResearch/hermes-agent, `AGENTS.md`, `agent/AGENTS.md`, `SECURITY.md`) | Одно ядро агента на CLI, десктоп, веб и 25+ мессенджеров через «шлюз» с адаптерами. «Ядро — узкая талия, возможности — по краям». Системный промпт **байт-в-байт стабилен** весь разговор; всё изменчивое идёт сообщением пользователя или результатом инструмента. Снимок «поверхности промпта» в CI: любая правка промпта/инструментов валит тест, пока снимок не обновлён и не одобрен. Цепочки запасных моделей, отдельные «вспомогательные» модели под задачи. Инструменты — таблицей, не цепочкой `if`. Отдельный документ модели доверия. Папка `evals/` с прогонами на живой модели | Всё перечисленное, в масштабе нашего продукта |
| **OpenAI Agents SDK** (github.com/openai/openai-agents-js, `docs/guides/guardrails`, `tracing`, `sessions`) | Три семейства проверок: на входе, на выходе, вокруг каждого инструмента; «растяжка» (tripwire) останавливает ход. Режим «проверить до вызова модели» — ради денег и безопасности. Трассы и отрезки (span) на каждый вызов модели и инструмента. Сессии — общий интерфейс памяти | Проверки вход/выход/инструмент; журнал-трассы; интерфейс памяти |
| **Mastra** (github.com/mastra-ai/mastra, `packages/memory`, `packages/evals`) | Память: история разговора, «рабочая память» (короткие факты о человеке), поиск по прошлому; разделение «разговор» и «человек». Оценщики (scorers) ответов | Рабочая память = наша `rememberFact` и план; оценщики для проверочного прогона |
| **Vercel AI SDK 7** (уже стоит у нас: `ai@7`) | `ToolLoopAgent`, промежуточные слои модели (`LanguageModelMiddleware`), реестр провайдеров (`createProviderRegistry`), потоковые ответы в интерфейс | Строим обвязку **поверх него**, без нового тяжёлого фреймворка |

Отвергнуто: LangChain и подобные «большие» фреймворки — лишний вес и слои; агент, который сам действует в мире, — коту не нужен.

## 2. Структура (`lib/ai/`)

```
каналы:  сайт (поток в чат) · Telegram · внешний API · будущее приложение
            │  тонкие адаптеры: только перевод формата канала ⇄ общий формат
            ▼
lib/ai/harness.ts   runTurn({ канал, задача, ввод, человек, поток? })  ← ЕДИНСТВЕННЫЙ вход к модели
  1. guards/input     размер, язык, признаки взлома промпта, кризис, возраст < 18
  2. context          данные человека (память, план, старты) — отдельным блоком-сообщением «данные, не инструкции»
  3. persona          системный промпт задачи — стабильный, из файлов, со снимком в CI
  4. models           задача → модель + запасные; лимит на первый токен; переключение
  5. tools            реестр инструментов + проверка аргументов (zod, длина)
  6. guards/output    тон без стыда, нет медсоветов, русский язык, длина → одна перегенерация или запасной ответ
  7. budget           лимиты токенов на человека/день и на весь продукт/день
  8. trace            журнал без личных данных: задача, модель, время, токены, переключения, срабатывания проверок
            ▼
провайдер: AnyModel (OpenAI-совместимый) → модель задачи
последний рубеж: заготовленные реплики кота (lib/scripted-companion) — кот не молчит никогда
```

Файлы (по принципу Hermes «фасад + соседи», каждый файл — одна тема):

| Файл | Что делает |
|---|---|
| `lib/ai/harness.ts` | `runTurn` и `streamTurn` — единственные функции, которые зовут модель |
| `lib/ai/tasks.ts` | Таблица задач: `chat`, `breakdown`, `sessionVoice`, `bot` → промпт, инструменты, модель, лимиты, бюджет времени |
| `lib/ai/persona/*.md` | Характер кота и правила тона — **один источник** для всех каналов; задачи добавляют своё |
| `lib/ai/context.ts` | Сборка блока данных человека (обрезка, экранирование, пометка «это данные») |
| `lib/ai/models.ts` | Реестр провайдеров и моделей, цепочки запасных, лимиты ожидания, выключение «рассуждения» |
| `lib/ai/tools.ts` | Реестр инструментов (`savePlan`, `rememberFact`, `startFocus`, …) таблицей |
| `lib/ai/guards/input.ts`, `output.ts` | Проверки: правила (быстро, бесплатно) + список стоп-фраз стыда/вины, медицины |
| `lib/ai/crisis.ts` | Кризисный протокол: фиксированный бережный ответ с телефонами помощи, без модели |
| `lib/ai/budget.ts` | Счётчики (сейчас — в памяти; с базой — общие) |
| `lib/ai/trace.ts` | Запись трасс (сейчас — логи Vercel; с базой — таблица) |
| `lib/ai/channels/web.ts`, `telegram.ts` | Адаптеры каналов |
| `evals/` | Проверочный прогон: 60–100 ситуаций + проверки; запуск в CI при изменении промпта/модели |

## 3. Неизменные правила обвязки (как «инварианты» Hermes)

1. **Любой вызов модели — только через `harness`.** Маршруты и бот не импортируют провайдера напрямую (проверка линтером).
2. **Системный промпт задачи стабилен и под снимком.** Изменился промпт или список инструментов — тест падает, пока снимок
   не обновлён в том же коммите (Hermes `prompt_surface`). Бонус: стабильный префикс кэшируется провайдером — дешевле и быстрее.
3. **Данные человека — не в системной инструкции**, а отдельным сообщением с пометкой «данные». Закрывает находку 4 аудита
   безопасности (текст из ссылки попадал в инструкцию).
4. **Кот не молчит.** Цепочка: основная модель → запасная → заготовленная реплика. Лимит на первый токен для каждой задачи.
5. **Кризис и медицина — без импровизации.** На кризисные сигналы — фиксированный проверенный ответ; советы про лекарства
   и диагноз модель не даёт (проверка на выходе).
6. **Лимиты до вызова модели** (режим OpenAI «проверить до»): исчерпан бюджет — заготовленная реплика, а не платный вызов.
7. **В журнале нет личных данных:** ни текста человека, ни памяти — только числа и коды.
8. **Ключи только на сервере** (переменные Vercel, Sensitive), никогда `NEXT_PUBLIC_`.
9. **Каждая плохая реплика из жизни становится ситуацией в проверочном прогоне** (как «каждый баг — тест»).

## 4. Модель и провайдер: замеры 11.11 (AnyModel, ключ владельца)

- AnyModel — OpenAI-совместимый посредник (`https://anymodel.org/v1`, 108 моделей по ключу). Подключается к AI SDK
  как OpenAI-совместимый провайдер (пакет `@ai-sdk/openai-compatible`).
- **DeepSeek V4 Flash (`ds/deepseek-v4-flash`)** — модель «с рассуждением»:
  - по умолчанию все 120 токенов ушли на рассуждение, ответ пустой, 23 с;
  - `reasoning_effort: "none"` выключает рассуждение (0 токенов рассуждения): ответы короткие, тёплые, по-русски;
  - **скорость сильно скачет во времени:** в 13:40 — 5,1 / 11,0 / 91,2 с, поток — первый байт через 17–34 с;
    в 14:05 — 2,1 и 2,7 с;
  - инструменты работают (вызов `save_step` с разумным шагом), один раз проскочило английское слово («не belongs»).
- Для сравнения в тот же час через тот же ключ: Gemini 2.5 Flash-Lite 1,3–2,2 с (значит, посредник сам не тормозит),
  Claude Haiku 5.5 2,5–4,2 с, GPT-6 Luna 7,8–8,2 с, Grok 4.20 non-reasoning 1,5–1,9 с (но ответ сухой, с эмодзи),
  Qwen 3.7 Plus 3,4–5,9 с, GLM-5.3 Flash 8,6–11,8 с.
- **Вывод для обвязки:** DeepSeek V4 Flash — основная модель (выбор владельца, качество хорошее), но с лимитом на первый
  токен (чат ~4 с, реплики сессии ~3 с, разбивка ~6 с) и автоматической запасной (кандидат по замеру — Claude Haiku 5.5:
  тёплый тон, 2,5–4 с; финальный выбор — по проверочному прогону). Рассуждение выключено во всех задачах реального времени.

## 5. Решения и риски для владельца

1. **Ключ был отправлен в чат.** Он сохранён только в песочнице сеанса (не в репозитории). После переноса в Vercel —
   выпустить новый ключ в AnyModel, а этот отозвать: переписки хранятся.
2. **Куда положить ключ навсегда:** Vercel → проект → Settings → Environment Variables → `ANYMODEL_API_KEY`, отметить
   Sensitive, окружения Production и Preview. Сделать это может только владелец (у меня нет доступа к панели Vercel).
3. **AnyModel — посредник:** тексты людей проходят через ещё одну компанию. Нужно прочитать их условия (хранение запросов,
   страна, обучение на данных) и вписать в `/privacy`. Связано с находкой 1 аудита безопасности (бесплатный Gemini и
   подростки): с переходом на AnyModel вопрос не исчезает, а меняет адресата.
4. **Одна точка отказа:** если AnyModel лежит, лежат все модели. Последний рубеж — заготовленные реплики; по желанию —
   второй провайдер как запасной (решение владельца).
5. **Деньги:** платим за токены. Лимиты на человека и на день — в обвязке; потолок трат — в кабинете AnyModel, если он там есть.

## 6. План внедрения (по шагам, каждый — с «было/стало» и тестами)

1. **Проверочный прогон на текущей версии** (60–100 ситуаций: тон, кризис, медицина, взлом промпта, разбивка, длина) —
   фиксируем, как кот отвечает сейчас.
2. **Ядро обвязки + провайдер AnyModel** за флагом; модели и запасные — в `models.ts`.
3. **Перенос задач по одной:** реплики сессии → разбивка → чат. Каждая — прогон не хуже, чем до.
4. **Telegram-бот** — через тот же `harness` (когда владелец решит вливать бота; закрывает и находки аудита по боту).
5. Журнал и лимиты переезжают в базу, когда она появится.
